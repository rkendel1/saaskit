# Raw DX log (evidence feed for FELTKIT_EXPERIENCE.md)
- [component] principal id "payments-gateway" accepted by `feltkit codegen`, refused only at ComponentHost.start ("neither component:payments nor an app.agent principal"). Error message excellent; validation late. COMPONENTS.md says refused "at definition, build and start" — definition (codegen/load) did NOT refuse.
- [integration] app.integration sends JSON only (runtime/integrations.js:288). Stripe API is form-encoded → cannot use app.integration for Stripe.
- [inbound webhooks] services.webhooks.inbound verifies AppPort's own x-appport-signature scheme only. Stripe-Signature (t=,v1=) not supported → provider events go through a component; AppPort's inbound event lifecycle (processing/failed/dead, replay) can't be reused.
- [tenancy] tenant-scoped collections closed to calls without tenant; no system/operator cross-tenant reader → billing state uses explicit accountId.
- [schedules] no ctx.services.schedules and no code-declared schedule; schedules run as the person who created them → lifecycle clock lives in the component.
- [intent] FeltDB "Intent" (@feltdb/core intent.d.ts) is NL→module implementation planning, not durable workflows.
- [deps] FeltKit 0.3.30 pins @appport/sdk 1.8.1 (latest 1.9.0), authorization 1.1.1 (1.2.0), server 1.3.2 (1.3.3), mcp 1.3.8 (1.3.9). Not overridable without violating FeltKit's no-overrides release check.
- [testing] createTestApp + ComponentHost.start(t.runtime,{from:"sources"}) lets tests drive the REAL component over real HTTP. Excellent. 31 tests, ~21s total.
- [tenancy] t.as(user,{tenant}) for a non-member → FORBIDDEN (no tenant role), stricter than docs' NOT_FOUND wording (HTTP path). Good outcome; doc nuance.
- [transactions] checked reads (phantoms) made concurrent metering correct with zero app locking code: 20 concurrent exports vs allowance 10 → exactly 10 committed, no lost updates. Retries are the caller's job (component ctx.call retries CONFLICT 4x automatically; test/clients need their own).
- [app bug found by tests] grace/dunning anchored to event-arrival time instead of due time.
- [audit] app.auditTrail record/history used for every material decision; ordering by per-subject FeltDB sequence. No custom audit infra needed.
- [authboundry] authority.local works offline with the native @authboundry/core binary (~6s first decision in tests, deferred start). Executor credential "proven". GAP: grants.grant maps the person to `user:<id>` (authority.principal default) but ctx.authority.decide({onBehalfOf}) passes the id verbatim → "delegation_missing" until the app prefixes `user:` itself. Asymmetric contract.
- [authboundry] QueryCtx type lacks `authority` though runtime provides it to queries (probe query called grants.list successfully) → cast workaround W-04.
- [authboundry] test state is per test app (`<state>.authority`); identical grant ids across runs are deterministic ids, not leakage (checked runtime/local-authority.js:54-66).
- [billing correctness, app] mid-period upgrade would have forgiven Pro overage under Business allowance → fixed with billedUnits + settle-on-upgrade.
